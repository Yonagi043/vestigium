# Vestigium 公开开发题

[English](README.md) · [复现说明](REPRODUCE_ZH.md)

这里是我们开发 Vestigium 时用的题目、答案键和证据。Vestigium 是给 AI agent 用的长 PDF 结构化阅读器，通过 MCP 工具使用。有了这些题，你可以用自己的 Claude Code 和模型重跑我们开发阶段的比较，也可以拿别的阅读器在同一批材料上测。

题目都出自公开文档：美国 GAO 报告、NIST 特别出版物、NASA 技术报告、arXiv 论文、苹果的财报和报告、港交所披露文件。**包里不含 PDF。** `documents.json` 写了每份文档的公开来源，以及出题时那份文件的 SHA-256。

正式确认用的题不在这个包里。它们继续保密，这样对外公布的结果不会建立在谁都可能调过的题上。

## 包里有什么

| 文件 | 内容 |
|---|---|
| `questions/*.jsonl` | 每行一道题：题目、答案要点（facets）和证据、参考答案、出题说明 |
| `documents.json` | 题目用到的每份文档：登记名、文件名、页数、SHA-256、公开链接、我们的下载核对结果。`vestigium eval fetch-docs` 读这个文件 |
| `documents.csv` | 同样内容的表格 |
| `REPRODUCE_ZH.md` | 怎样重跑开发阶段的比较，以及正式确认是怎么做的 |
| `selfcheck.json` | 对本包的扫描：私有路径、密钥、保密题号，命中 0 处 |
| `MANIFEST.json` | 计数，以及每个文件的 SHA-256 |

## 几套题

| 题集 | 题数 | 可回答 | 必答要点 | 需要两份文档 | 文档数 |
|---|---|---|---|---|---|
| `old57` | 57 | 52 | 309 | 0 | 13 |
| `dev` | 15 | 13 | 61 | 0 | 7 |
| `dev2` | 25 | 22 | 125 | 0 | 10 |
| `dev3` | 10 | 9 | 60 | 2 | 9 |
| `vis_dev` | 15 | 14 | 43 | 0 | 12 |

- `old57`：在项目结果页那次比较之前，我们另一次比较用过的 57 道测试题，之后转为开发题，所以已经不是“没人见过的题”。那次早先比较的数字不在结果页上。
- `dev`、`dev2`、`dev3` 是文字题。`dev3` 每题的要点最多（平均约 7 个），有两道题要用两份文档。
- `vis_dev` 的答案在图、图表、地图或扫描的表格里，只能从页面图像上读，PDF 的文字层里没有。
- 不可回答题（文档里没有答案，或者题目前提有误）检验阅读器会不会老实说“没有”。
- 全部题共用 30 份文档。

这些题在开发中被看过、用过，每题的要点也比正式确认的题少（平均约 6 个，确认题约 9 个）。适合用来检查环境、比较不同的阅读器，不适合用来对“没见过的题”下结论。

## 题目格式

```json
{"id": "...", "set": "dev3", "split": "dev", "doc": "<登记名>", "docs": ["<登记名>", "..."],
 "question": "...", "types": ["table_cell", "compare"], "hops": 2, "unanswerable": false,
 "facets": [{"id": "f1", "text": "<正确答案要说出的内容>", "required": true,
             "evidence": [{"pdf_page": 25, "printed_page": "22", "ref": "#/tables/4", "quote": "..."}]}],
 "reference_answer": "...", "notes": "<认可的写法、容差、容易混淆的值>", "checks": {...}}
```

- `doc` 是题目自己的文档；`docs` 还列出证据用到的其他文档。名字和 `documents.json` 一致。
- 来自另一份文档的证据带自己的 `doc` 字段（用两份文档的题里会有）；没写 `doc` 的证据来自题目自己的 `doc`。
- `pdf_page` 从 PDF 文件的第一页数起，不是印刷页码；`printed_page` 是页面上印的页码（有的话）。
- `ref` 是证据所在的 Docling 条目，按我们用的 Docling 版本编号。换一个 Docling 版本，编号可能不同；页码和引文不受影响。
- 图像证据写成 `{"page", "bbox": [左, 上, 右, 下], "kind": "image", "what", "probes"}`：框的单位是 PDF 点，按页面显示的方向，原点在左下角。`probes` 是只能从图上读出的值。
- `checks` 记录每道题是怎么核对的：出题人自己的阅读，以及另开的 agent 盲答后和答案键的比对。`vis_dev` 里的 DI、DT、WT 分别指只给页面图像、只给页面文字、给整篇文字的盲答核对。底层记录是内部的，没有公开。

## 获取文档

```bash
vestigium eval fetch-docs documents.json --out pdfs --ingest-script ingest.sh
```

它从公开链接逐个下载 PDF，再和 `documents.json` 里的 SHA-256 比对。`pdfs/` 里已有、而且 SHA-256 对得上的文件会保留，所以你可以在浏览器里下载，按清单里的文件名放进 `pdfs/`，再运行一次。

港交所和 Apple 的链接以后可能失效。从别处下载的副本，只要 SHA-256 和 `documents.json` 一致就能用：按清单里的文件名放进 `pdfs/` 即可。

我们 2026-10-22 在自己的服务器上核对的结果：

- 30 份里 25 份和 SHA-256 完全一致。
- `nist__NIST.SP.800-63-4`：NIST 现在提供的文件字节不同，但同样是 96 页，每页文字层和我们的完全一样，所以题目照样成立。它的 SHA-256 列在 `alt_sha256` 里，`fetch-docs` 也接受这个文件（报告为 `alternative`）。
- 4 份 GAO 报告从我们的服务器下载被拒（gao.gov 返回 HTTP 403），没有核对。这些链接在普通浏览器里可以打开。

每份文件的结果见 `documents.json` 的 `check` 和 `check_note` 两栏。

## 判分口径

每个必答要点给一个判定：

| 判定 | 含义 |
|---|---|
| correct 对 | 说出了要点的内容；等价说法和出题说明认可的写法都算 |
| partial 部分对 | 只说出一部分（比如两个数只给了一个），或者不够精确但没说错 |
| wrong 错 | 答了这一点，但和文档不符，或者拿了文档里别处的值 |
| missing 没写 | 没答这一点 |
| fabricated 编造 | 给出文档里哪儿都没有的具体值或结论 |

不可回答题只有一个要点：明确说“文档里没有”判对；说了没有、又猜一个值，判编造。严格准确率只算“对”；宽松准确率把“部分对”也算上。页码引用不计分。
