0.1.1 版加了由工具自己执行的[规则](RULES_ZH.md)，以及[每次阅读的记录](TRACES_ZH.md)。按发布默认，只开一条规则：一节接到下一页时，把下一页也读上。`trace`、`rules` 两个工具默认关，要用时再打开。

结果每次运行都有波动，所以每个数都附上范围。下面的差别都不够大，不能说 0.1.1 比 0.1.0 更准、更省或更快。

## 59 道新题上的确认

59 道新题的确认只做了一次，做在 0.1.1 的测试配置上。测试配置除了这一条规则，还多开了两条：搜索 0 处时给证据、反复搜索多次后给小结。两个工具也开着。

| | 0.1.1 测试配置对 0.1.0 | 95% 区间 |
|---|---|---|
| 准确率 | **+1.08 个点** | −0.40 到 +2.68：不比 0.1.0 差（界限 3 个点），不能说更准 |
| 花费（÷ 0.1.0） | **0.988** | 0.928 到 1.050：达到了事先定的花费规则（比值不超过 1.00）；区间包着 1 |
| 用时（÷ 0.1.0） | **0.99** | 0.94 到 1.04：没有看出差别 |

全部运行合计，“停早了”造成的丢分从 2 个降到 0。

这批题只用来确认一次，所以 0.1.1 的发布默认没有再拿它们考。发布默认比测试配置更接近 0.1.0，但说它在这批题上也不比 0.1.0 差，只是推断，没有实测。

19 道题，每种设置各跑 2 遍，模型是 `claude-opus-5-5`：每种设置几乎全对，对照题和不可答题全对。

两个区间都包着 1，看不出更贵。用时两种都是 1.07：工具关 1.07（0.99 到 1.16），工具开 1.07（0.95 到 1.23）。

## 已知的薄弱处

- **停早了。** 事先定的目标是把“停早了”造成的丢分减少三分之二，这次没达到：丢的要点从 6 个降到 3 个，只减了一半；数也太少，看不出能不能减少三分之二。
- **读到了没写。** 这是模型那边的事，工具管不到。
- **写规则。** Haiku 写对规则 60%，Opus 20 题全对。设置规则时建议用强一点的模型。

## 其他检查

- **语言够小。** 两个新工具的说明合计约 300 token（按我们自己的计数器）；54 条写错的规则全部被拒，每条都给了改法。
- **AI 助手读得懂轨迹。** Haiku 88%，Opus 100%。
- **不退步。** 规则全关时，在我们测过的文档上，返回和 0.1.0 逐字节相同。
- **边界。** 轨迹和规则只存本机（断网实测 0 次连网）；撤销、恢复出厂、全部关掉都能用。

## 还不能说明的

- 0.1.1 比 0.1.0 更准、更省或更快：差别都在波动范围以内。
- 0.1.1 的发布默认自己通过了 59 道新题的确认：那是在测试配置上做的。
- 看得见阅读记录、能写规则，实际用处有多大：这两个工具默认关着，它们的价值还没有测过。
- Claude Code 以外的外壳、Claude 以外的模型。
- 你自己写的规则效果如何。
- AI 判分和人的判断一致：0.1.1 没有做人工抽检。
