# 同类项目

[English](RELATED.md) · [README](../README_ZH.md)

已经有一些项目让语言模型通过树形结构或分层的方式读长文档，而不是把文档切成一堆平铺的小块。本页按各项目自己的说法简单介绍其中几个，并说明 Vestigium（迹）在设计和测试方法上有哪些不同。

**我们没有在自己的题上跑过这些项目，也没有在它们的测试集上跑过 Vestigium。** 它们公布的数字来自别的测试集和设置。本页的任何内容都不是在说 Vestigium 比它们更准或更省。

来源核对于 2026 年 10 月 22 日。

## 一览

| 项目 | 结构怎么建 | 提问时由谁沿着结构找 | 指向的单位 | 怎么评测 |
|---|---|---|---|---|
| [PageIndex](https://github.com/VectifyAI/PageIndex) | 按文档版面建树，再由语言模型写摘要、做整理 | 语言模型在树上推理 | 页（本地版）；块（托管的 Cloud 版） | 厂商自报 FinanceBench 和自建测试集上的结果 |
| [RAPTOR](https://arxiv.org/abs/2401.18059) | 文本块先向量化、聚类，再由语言模型逐层写摘要，自下而上 | 按向量相似度检索，模型不导航 | 文本块 | NarrativeQA、QASPER、QuALITY |
| [NavTree](https://arxiv.org/abs/2610.06902) | 在文本块上建一棵固定的平衡树，不调模型 | 关键词加向量的检索沿树往下走，模型不导航 | 文本块 | QuALITY、QASPER、NarrativeQA 和另外三个多跳问答集 |
| [DeepRead](https://arxiv.org/abs/2602.05014) | OCR 转成 Markdown，标题作为节点，每段有一个坐标 | 语言模型代理，用“检索”和“读一节”两个工具 | 节和段的坐标 | FinanceBench、自建的 ContextBench，以及 QASPER、SyllabusQA 的多文档版本 |
| [MemWalker](https://arxiv.org/abs/2310.05029) | 语言模型写出的摘要节点组成的树 | 模型沿树导航 | 文本片段 | 长文本问答 |
| **Vestigium** | Docling 的版面结果加固定规则：章节、印刷页码、交叉引用、定义、表格。不调模型，不用向量 | 用户自己的 AI 助手，通过 6 个 MCP 工具 | PDF 页码，附印刷页码 | 在 Claude Code 里，和整篇文本、直接读 PDF 比较，方法事先登记 |

## 分别说几句

- **PageIndex**（VectifyAI，2025；MIT 许可证）自称“不用向量、靠推理的 RAG”。它的 README 说，树的结构是从文档版面提取的，不用语言模型；建索引的模型只负责写摘要和整理。开源包处理有文字层的 PDF，在你自己的机器上跑，用你自己的模型密钥。托管的 Cloud 版另外提供 OCR、图像理解和 MCP 服务。README 报告在 FinanceBench 上准确率 98.7%，这是厂商自己的数字。
- **RAPTOR**（Sarthi 等，ICLR 2024）把文本块反复“向量化、聚类、写摘要”，建成一棵树。检索时按向量相似度挑节点，可以沿树往下走，也可以在所有层上一起找。它是检索流水线，不是代理；树是按主题聚类形成的，不是文档自己的章节。
- **NavTree**（Jayraj、Goyal、Goyal，arXiv 预印本 2610.06902，2026）问的是：摘要到底有没有必要。它建一棵确定性的树，建索引时“不调用任何语言模型”，并在花费相当的条件下和带摘要的树做了比较。
- **DeepRead**（Li 等，arXiv 预印本，2026）思路上和 Vestigium 最接近：代理先定位、再阅读（“locate-then-read”），每段都有可以引用的地址。它用一个 OCR 模型还原文档的标题层级。
- **MemWalker**（Chen 等，2023）是较早的例子：模型沿着一棵摘要树往下走，找到长文本里需要的部分。

## Vestigium 的不同之处

Vestigium 的读法和上面这些项目有不少相同之处：PageIndex 也指向页码、也能在本地运行，NavTree 建索引也不调模型，DeepRead 也给代理按地址读文档的工具。我们能说的不同，主要在怎么测。下面没有一条是在说效果更好。

- **在真实的 AI 外壳里测，和公平的对照组比，检验方法事先写死。** 我们在 Claude Code 里测 Vestigium，外壳自己的提示词、工具、上限、缓存都在。对照组也是外壳自己的读法：整篇文本加外壳自带的搜索，以及直接读 PDF。我们最初的整篇文本对照组吃了亏，因为 Claude Code 会藏起长行，正式测试前已经修好。题是新出的，分析方法事先定死，数字由另一个代理独立复算。见[方法](METHODS_ZH.md)。
- **本地运行。** 解析、建索引、提供服务都在你自己的机器上；调用模型的只有你的 AI 助手自己。
- **按地址读。** 助手通过 6 个工具，用短地址搜索和读取节、页、表、图，每段内容都带 PDF 页码。
