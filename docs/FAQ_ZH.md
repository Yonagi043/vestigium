# 局限和常见问题

[English](FAQ.md) · [README](../README_ZH.md)

## 已知局限

- **测试范围窄。** 正式测试只用了英文的长篇公开报告（公司财报、政府报告、标准、论文、NASA 技术报告），只在 Claude Code 里测，只用 Claude 模型。中文只做过一次小试。
- **小模型看图弱。** 要看图表或示意图的题上，Haiku 用 Vestigium（迹）只答对 33%。`region` 能把图交给模型，但小模型常常看错。Opus 在这类题上没测。
- **中文是实验性支持。** 在 15 道中文开发题上，Haiku 用 Vestigium 得 96.0%，整篇中文全文 96.5%，花费约一半。三种用法都在 96 分以上，这批题偏容易，看不出难题上的差别。见[结果](RESULTS_ZH.md#中文实验性)。
- **解析决定上限。** Vestigium 只能提供 Docling 提取出来的内容。扫描件、旋转的页、复杂的表格、少见的版面，都可能丢字或放错位置。每加入一份 PDF，请用 `vestigium ingest qc 名字` 看一眼它的质检报告。已知的弱点有：扫描页上旋转了 90° 的文字读不出来（质检报告会把这种页标成 `no_text`）；扫描页上的 OCR 可能把部分繁体字认成简体；Docling 偶尔会把一整页当成一张表；我们试过的每个 Docling 版本都有表格结构出错的情况。
- **准确率是“不差”，不是“更好”。** 和把整篇文本交给模型相比，Vestigium 不差 5 个点以上，花费约一半。没有证据说明它更准。
- **AI 判分。** 测试答案由 Claude Opus 判分代理来判，人工抽检还没做。

## 常见问题

### 该用哪个模型？

最看重准确，用 Claude Opus 加 Vestigium：在我们 27 道文字难题上接近满分。不过 Opus 读整篇文本也有 99.6%，这次测试分不出两者高低。最看重花费，用 Claude Haiku 加 Vestigium：同样的题约 92%，按标价每题约 6.5 美分。别的模型都算实验性。

### 能省钱吗？

看你怎么付费。

- **按 token 计费**（比如用 API 密钥）：这次测试里能省。Haiku 用 Vestigium 的花费，约是 Haiku 读整篇文本的一半、读 PDF 的四分之一。
- **按请求或按消息计费**（有些订阅套餐是这样）：不一定省。Vestigium 省的是 token；套餐不按 token 收钱，就体现不出来。这种情况我们没有实测。

不管哪种计费方式，用 Haiku 时，Vestigium 的用时都约是整篇文本的一半（用 Opus 时是 0.87）。

### 我的文档会被发到别处吗？

Vestigium 本身在你自己的机器上运行：解析、建索引、提供服务都在本地，服务和你的 AI 外壳也在同一台机器上通信。但 AI 助手读到的段落，会发给它所用的模型，就跟你把这些段落粘贴进对话一样。如果文档不能离开你的机器，请用本地模型。可选的 HTTP 服务没有登录验证，请让它保持默认的 127.0.0.1（见[各客户端的接法](CLIENTS_ZH.md)）。阅读的记录和 AI 助手写的规则也只存在你的机器上。记录里不存文档段落，但会存 AI 助手的搜索词，它可能抄了文档里的短语；见[轨迹](TRACES_ZH.md#存了什么存在哪里)和[规则](RULES_ZH.md#存了什么存在哪里)。

### 建索引时用语言模型吗？

不用。Docling 用的是它自己的版面、表格和 OCR 模型，都在本地运行。Vestigium 在这之上加的章节、页码、交叉引用、定义、表格，全部来自固定规则。不生成摘要，所以索引里没有任何改写过的内容。

### 需要 GPU 吗？

不需要。Docling 能在 CPU 上跑，有 GPU 会快一些。我们服务器上的实测（GPU 和 24 核 CPU 都和别的项目共用、负载不低，所以下面的数可以当上限看）：

| 页面 | 有 GPU | 只用 CPU |
|---|---|---|
| 原生电子版的文字页 | 每页 0.3–0.7 秒 | 每页约 1.6 秒 |
| 扫描页，由 OCR 补空 | 每页 2–6 秒 | 每页 4–7 秒 |

OCR 不管有没有 GPU 都在 CPU 上跑。建 Vestigium 的地图每份文档另需 3–18 秒。第一次转换还要下载 Docling 的模型（约 0.6 GB）。装了 Docling 的 Python 环境在我们服务器上约占 6 GB，大头是 PyTorch。在 Linux 上，`[ingest]` 会通过 PyTorch 装上 NVIDIA 的 CUDA 库，它们有自己的许可证；先装只用 CPU 的 PyTorch 应该能避开它们，但这种装法我们没有测过。

### 能离线用吗？

能，但要先下载一次。计算 token 用的 tiktoken 第一次运行时，会下载词表文件 `o200k_base`（约 3.6 MB，来自 `openaipublic.blob.core.windows.net`）并缓存起来。在不能上网的机器上，要先把这个文件放进缓存目录，并用 `TIKTOKEN_CACHE_DIR` 指向它；否则 `vestigium mcp` 第一次计算 token 时会报错。另外，第一次处理 PDF 时，Docling 也要下载它的模型（约 0.6 GB）；可以在联网时先运行 `docling-tools models download layout tableformer rapidocr`，提前下好。

### 能处理扫描件吗？

能，靠 Docling 的 OCR，但 OCR 出来的文字可能有错。我们的文档里就有 NASA 的扫描报告。来自 OCR 的文字会标明是 OCR，并提醒可能有错。文字看起来不对时，AI 助手可以用 `region` 直接看那一页。

### 为什么答案有时会漏项？

我们的测试里，丢分大多是答案里漏了项，而不是事实写错。开发阶段 Haiku 的运行里，30–47% 的丢分是证据已经交给了模型、却没写进答案。遇到要列举的问题，请自己核对一下数目。明确要求“逐项列全”也许有帮助，但我们没有测过。

### 一个会话里能连问好几个问题吗？

互不相关的问题，每题开一个新会话（或子代理）通常更省。离线模拟显示，把一串问题塞进一个长会话，按标价算花费是分开问的 1.1 到 1.2 倍（按输入 token 算是 1.2 到 1.5 倍），因为外壳每一轮都要把整段对话重读一遍。

### 能在 VS Code、Cursor 或别的软件里用吗？

支持 MCP 服务的软件按说应该能接上，见[各客户端的接法](CLIENTS_ZH.md)。我们只在 Claude Code 里测过。别的软件有各自的输出上限，处理图片的方式也可能不同。如果你的软件不支持 MCP，或者单位把 MCP 关掉了，可以改用导出的文件版。

### 能配 GPT、Gemini 或开源模型吗？

服务本身不依赖 Claude，你的 AI 外壳支持的其他模型按说也能调用它。小检查里，一个 GPT 模型在 5 道开发题上用这些工具没有出错。这说明工具在它上面能用，说明不了它准不准；其他模型都算实验性。

### 我的结果会和你们的一样吗？

不会完全一样。结果取决于：

- **Docling 的版本和 OCR 引擎**：Vestigium 钉在 Docling 2.117.0。我们测试用的文档是在 Mac 上用这个版本解析的，OCR 用的是苹果的引擎；`vestigium ingest` 用的是 RapidOCR，所以扫描页的结果会不一样（我们的对比里，错位的重复行少了很多）。更新的 Docling 版本能认出更多表格，但会把扫描页自带的文字层换成重新 OCR 的结果，在我们的对比里把打字机扫描件弄成了乱码，所以我们暂时没有升级。
- **AI 外壳和它的版本**：我们用的是 Claude Code 2.1.283。
- **题目**：我们用的是长篇报告上的难题。
- **随机性**：我们的测试里，同一道题跑两次，花费相差的中位数是 13–23%。

怎样在随发布一起提供的开发题上重跑我们的比较，见[方法](METHODS_ZH.md#复现)。
